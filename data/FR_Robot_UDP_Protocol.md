# 法奥机器人 UDP 扩展轴通信协议说明

> 基于实际抓包分析的真实通信协议文档
> 分析日期: 2026年1月

## 1. 协议概述

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 通信方式 | UDP |
| 默认端口 | 8211 |
| 通信周期 | ~2ms |
| 支持轴数 | 4轴 |
| 帧头标识 | 0x5A5A |

### 1.2 数据包长度

| 方向 | 长度 | 说明 |
|------|------|------|
| 机器人 → PLC | 154 字节 | 控制命令包 |
| PLC → 机器人 | 160 字节 | 状态反馈包 |

## 2. 机器人发送数据包 (154字节)

### 2.1 总体结构

```
偏移    长度    说明
0-1     2      帧头 (0x5A5A)
2-29    28     轴1控制数据
30-57   28     轴2控制数据
58-85   28     轴3控制数据
86-113  28     轴4控制数据
114-129 16     DO输出 (8×UINT16)
130-137 8      AO输出 (4×INT16)
138-143 6      保留区域
144-145 2      帧计数 (UINT16)
146-153 8      保留/校验
```

### 2.2 单轴控制数据结构 (28字节/轴)

```
偏移    寄存器    类型      说明
0-1     D200     INT16     控制命令字
2-5     D201     DINT32    目标位置命令 (脉冲)
6-7     D203     UINT16    回零命令字
8-11    D204     DINT32    回零高速度命令 (脉冲/s)
12-15   D206     DINT32    回零低速度命令 (脉冲/s)
16-19   D208     DINT32    位置偏置
20-23   D210     DINT32    速度偏置
24-27   D212     DINT32    转矩偏置
```

### 2.3 控制命令字 (D200)

| 位 | 值 | 说明 |
|----|-----|------|
| bit0 | 0x0001 | 使能 |
| bit1-15 | - | 保留 (实际未使用) |

**实际协议特点:**
- 只使用 bit0 (使能位)
- 运动控制通过改变目标位置 (D201) 实现
- 无需额外的启动/停止控制位

### 2.4 回零命令字 (D203)

| 位 | 值 | 说明 |
|----|-----|------|
| bit0 | 0x0001 | 回零启动 |
| bit12 | 0x1000 | 回零模式 |

**典型值:**
- `0x0000` - 无回零命令
- `0x1001` - 启动回零 (bit0 + bit12)

**回零触发条件:**
- 当回零命令字从 0x0000 变为 0x1001 时触发
- 回零命令与控制字使能状态独立
- 机器人发送回零命令时控制字可能为 0x0000

## 3. PLC反馈数据包 (160字节)

### 3.1 总体结构

```
偏移    长度    说明
0-1     2      帧头 (0x5A5A)
2-31    30     轴1状态数据
32-61   30     轴2状态数据
62-91   30     轴3状态数据
92-121  30     轴4状态数据
122-137 16     DI输入 (8×UINT16)
138-145 8      AI输入 (4×INT16)
146-155 10     保留区域
156-157 2      帧计数 (UINT16)
158-159 2      CRC16校验
```

### 3.2 单轴状态数据结构 (30字节/轴)

```
偏移    寄存器    类型      说明
0-1     D100     INT16     状态字
2-5     D101     DINT32    当前位置 (脉冲)
6-7     D103     INT16     回零状态字
8-11    D104     DINT32    寻零速度反馈 (脉冲/s)
12-15   D106     DINT32    爬行速度反馈 (脉冲/s)
16-17   D108     INT16     故障码
18-21   D109     DINT32    随动偏差量
22-25   D111     DINT32    速度反馈 (脉冲/s)
26-29   D113     DINT32    实时转矩
```

### 3.3 状态字 (D100)

| 值 | 说明 |
|-----|------|
| 0x0002 | 已使能 (默认/回零完成后) |
| 0x0003 | 就绪+已使能 (运行中/回零中) |

**状态字位定义:**
| 位 | 值 | 说明 |
|----|-----|------|
| bit0 | 0x0001 | 就绪 |
| bit1 | 0x0002 | 已使能 |

**实际协议行为:**
- PLC 上电后默认响应 0x0002 (已使能)
- 收到使能命令后响应 0x0003 (就绪+已使能)
- 回零完成后状态字变回 0x0002

### 3.4 回零状态字 (D103)

| 值 | 说明 |
|-----|------|
| 0x0000 | 未回零 |
| 0x0001 | 回零中 |
| 0x0002 | 回零完成 |
| 0x0004 | 回零错误 |

## 4. 通信时序

### 4.1 正常通信流程

```
机器人                              PLC
  |                                  |
  |------ 控制包 (154字节) --------->|
  |                                  |
  |<----- 状态包 (160字节) ----------|
  |                                  |
  |------ 控制包 (154字节) --------->|
  |                                  |
  ...     (约2ms周期)              ...
```

### 4.2 使能流程

```
1. 机器人发送: 控制字=0x0001 (使能)
2. PLC响应:   状态字=0x0003 (就绪+已使能)
3. 持续通信...
4. 机器人发送: 控制字=0x0000 (去使能)
5. PLC响应:   状态字=0x0002 (已使能/待机)
```

### 4.3 回零流程

```
1. 机器人发送: 回零控制=0x1001, 高速=xxx, 低速=xxx
   (控制字可能为0x0000)
2. PLC响应:   状态字=0x0003, 回零状态=0x0001 (回零中)
3. PLC执行回零运动...
4. 回零完成后:
   PLC响应:   状态字=0x0002, 回零状态=0x0002, 位置=0
5. 机器人发送: 回零控制=0x0000 (清除回零命令)
```

### 4.4 位置控制流程

```
1. 机器人发送: 控制字=0x0001, 目标位置=xxx
2. PLC响应:   当前位置逐渐变化
3. 到达目标后: 当前位置=目标位置
```

## 5. CRC16 校验

### 5.1 算法说明

使用 Modbus CRC16 算法:
- 初始值: 0xFFFF
- 多项式: 0xA001
- 计算范围: 前 158 字节

### 5.2 Python 实现

```python
def calc_crc16(data: bytes) -> int:
    crc = 0xFFFF
    for byte in data:
        crc ^= byte
        for _ in range(8):
            if crc & 0x0001:
                crc = (crc >> 1) ^ 0xA001
            else:
                crc >>= 1
    return crc
```

## 7. 常见问题

### 7.1 连接失败

**可能原因:**
1. PLC 未响应状态字 0x0002 或 0x0003
2. 网络配置错误
3. 端口被占用

**解决方法:**
- 确保 PLC 在上电后立即响应 0x0002 状态
- 检查网络连通性
- 确认端口 8211 未被其他程序占用

### 7.2 回零失败

**可能原因:**
1. 回零控制字识别错误 (应为 0x1001)
2. 未正确响应回零状态字

**解决方法:**
- 检测 bit0 (0x0001) 上升沿触发回零
- 回零中响应回零状态=0x0001
- 回零完成响应回零状态=0x0002, 位置=0

### 7.3 运动不响应

**可能原因:**
1. 未响应正确的状态字
2. 位置反馈未更新

**解决方法:**
- 确保状态字在使能后为 0x0003
- 当前位置需要实时跟踪目标位置变化

## 附录: 字节序

所有多字节数据均采用**小端序 (Little-Endian)**:
- 低字节在前，高字节在后
- 例如: 0x1234 存储为 [34 12]

### 9.2 位置单位换算 (抓包验证)

**UDP协议中直接使用脉冲数，换算公式:**
```
脉冲数 = 位移(mm) × 编码器分辨率 / 导程
脉冲数 = 位移(mm) × 262144 / 14.990
脉冲数 ≈ 位移(mm) × 17,488.3
```

**抓包实测验证:**
| 位移(mm) | 理论脉冲数 | 抓包实测值 | 误差 |
|----------|-----------|-----------|------|
| -50mm | -874,409 | **-874,120** | 0.03% |
| ~0mm | 0 | **-882** | - |
| -49.9mm | -872,660 | **-873,045** | 0.04% |

**反向换算 (脉冲转mm):**
```
位移(mm) = 脉冲数 × 导程 / 编码器分辨率
位移(mm) = 脉冲数 × 14.990 / 262144
位移(mm) ≈ 脉冲数 × 0.0000572
```

**示例换算表:**
| 位移(mm) | 脉冲数 |
|----------|--------|
| 50mm | ~874,409 |
| -50mm | ~-874,409 |
| 10mm | ~174,883 |
| 1mm | ~17,488 |
| 0.1mm | ~1,749 |
| 0.01mm | ~175 |

> **注意**: 机器人配置界面中的限位值(50000/-50000)是用户单位(0.001mm精度)，
> 但UDP协议中传输的目标位置和当前位置是**脉冲数**。

### 9.3 速度单位换算

**速度换算公式:**
```
脉冲/s = 速度(mm/s) × 编码器分辨率 / 导程
脉冲/s = 速度(mm/s) × 262144 / 14.990
脉冲/s ≈ 速度(mm/s) × 17488.3
```

**示例:**
| 速度 | 脉冲/s |
|------|--------|
| 1000 mm/s | ~17,488,326 |
| 100 mm/s | ~1,748,833 |
| 10 mm/s | ~174,883 |
